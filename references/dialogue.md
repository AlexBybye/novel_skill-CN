# 人物对话生成与独立审查

用于连续互动的写作、重写与诊断。全章精修同时读[场景精修](scene-revision.md)，批量任务再按[批次执行](revision-batches.md)管理范围；不要每次加载全部对白案例与细则。

## 先分开两种需要

先锁定已授权情节、知情、误信、关系阶段、关键证词和结果，再分清读者需要知道什么，与每个人此刻想从眼前人那里得到什么。必要说明可以说清，双方已知的事也可因追责或亲近重提；人物不负责轮流念设定表。只更新skill不试改章节，审阅不自动授权写回。

## 动笔前：让每人有自己的开口理由

读取场内个人卡的适用部分及当前关系、知情和压力。想清此人为何此时对眼前人开口、想要怎样的回应、听进哪一部分、愿意说到哪里。没有隐藏欲望、转折和分歧可以照实保留，不强造秘密或冲突。全章任务的六项小卡只在[场景精修](scene-revision.md)维护，不重复填一份人物卡。

## 成文：一口话与整场相处

先写此人想说到的地方，再让对方从实际听到、在意或回避的部分接下去。不要把一个念头切成逐问逐答；长短随人和处境变化。动作、神态、心理、手边事情与环境处在同一时间中，可以跨过几轮，不为每句配动作。私有心理不能成为别人回应的依据。结束可因事情解决、有人不愿继续、事务打断或一起做事；听懂不等于消气，消气也不等于关系修复。

### 机械顶嘴与机械应答

通读整场，找是否总在抓词反问、纠正对方没说过的意思、认同后仍回顶，或逐格验收事实与正确立场。能接得上、有动机、未和解均不豁免。先重看真实关切和连续活动，不统一换成沉默、笑、长解释或动作补丁。真实争执、必要确认和有意拌嘴可保留；细分判断见[机械应答修法](details/dialogue.md#机械顶嘴与机械应答)。

## 口语完整性与精修优先级

依次处理语义和正常口语、人物关系与习惯、实际接话、重复解析旁白。自然不等于简短、潜台词多或全句化；完整词也可能像工作摘要。保留有内容的心理和有意粗粝，不凭禁词、句长或比例批改。具体辨认见[口语完整性](details/dialogue.md#口语完整性与精修优先级)。

## 信息分层与认知路径

新概念先依附已知的人和事，一层回答接住一层问题，插话后能回接；区分真正回答、不知道和拒答。不同人物从自己的关切参与，不能永久分配提问者、讲解者和风险提醒者。背景多而难理解时读[信息分层](details/dialogue.md#信息分层与认知路径)，不要先加一轮核验。

## 话如何被场内人听见和使用

同一句话可能在索取事实、态度、承认或让步，也可说给一人、让其他人听。多人交流或讲述卡在这里时，选读[听众与话语作用](dialogue-audience.md)；句子和动作的连续过程需要具体校准时选读[场景锚点](dialogue-in-scene.md)。案例只说明机制，不是可复用台词。

## 第二次审查：完整对话与人物行为

复读时先按[口语完整性与精修优先级](#口语完整性与精修优先级)检查被压缩、抽象化或书面化的表达，再沿下列既有判据检查整场；逻辑正确不能抵消说话生硬。

先完成[第一次情节审查](event-progression.md#交付前分两次审查)，再以完整对手戏为单位重读台词、行动、内心和停止交谈的方式，先定位实际读感损失，再用下列判据追查原因；判据不要求新增冲突、动作、潜台词或完美沟通。不能只审摘出的台词，也不能因逻辑准确便把第二次审查勾完。每章检查下列七项，跨章同一场还要连读；独立片段只对实际覆盖的范围负责。

| 验收项 | 看什么证据；失败时怎么处理 |
|---|---|
| 人物声音可辨认 | 遮去姓名看完整来回中的关注、组织话的方式和待人差别，再看同一人对不同对象的变化。普通“嗯”“饭还热着”无需单独可猜身份；若整场可任意换名，回到语言行为与关系重做。 |
| 没有问答清单与机械接招 | 连续回应是否只在交付下一条事实，或抓词反问、逐句纠正、总争最后一句；上一句带来的受挫、顾虑或愿望有没有进入下一句。按[机械顶嘴与机械应答](#机械顶嘴与机械应答)检查整场与可比关系场，不以逻辑成立或有动机豁免。真正的审讯、查证、普通短答与有意拌嘴不因形式相似判错。 |
| 重要对话有关系作用 | 指出哪一句或哪个行动改变或暴露了距离、信任、态度、权力及其代价；仅核实事实不能替代本应发生的关系转折。普通手续和稳定日常可不适用，不为过关制造新关系事件。 |
| 没有机械动作补丁 | 拿掉动作标签后，问题是否仍是相同的清单问答。动作和沉默为何在这里成立，有没有把每句话译成一个身体信号；不能靠多添动作判通过。 |
| 人物不替作者解释 | 台词为何说给眼前人听，而非只供读者补课。信息密集场另按[认知路径](#信息分层与认知路径)核对主问题、新概念锚点、回答与拒答及插话回接；不以事实齐全或人物有动机代替。必要背景可走合适的叙事通路；共同已知内容若在施压或亲近，保留其用处，不机械删去。 |
| 没有整齐的情绪解决 | 是否默认按质问、解释、理解、道歉、共情、总结一次完成；结尾是否服从既定人物关系和本场需要。作者已经确定的和解仍应保留，不强制每场留怨。 |
| 事实与关系未被篡改 | 对照写前边界及相邻实际稿：事实、动机、伏笔、知识范围、表达媒介、关系阶段和后续承接有没有被改掉。不能用新增敌意、告白或提前揭密换取戏剧性。 |

记录每项为“通过／待修／不适用”，随实际场景留简短引句或位置及判断；重复问题可共用证据，不必七段长报告。没有对白可标第二遍“不适用”，并检查人物行为，不假报七项通过。任一适用项仍待修时，不报本章对白达标；在当前授权内改整场，再复读受影响交流。无法在既定因果内解决的矛盾明确留下，不用总分或其余项通过抵消。

第二遍不是把人物话里的不准确都纠正成正确答案。区分角色有理由说错与作者写错；第七项检查作者边界，不要求人物自己解释边界。表达修整后仅针对受影响的事实与承接复核，发现越界撤回越界改动，不把人物重新修成准确传话器。

程序可标出高频句式、连续问答、重复指令，输出候选位置即可，不能凭次数判错、自动替换、打自然度分数或代替编辑判断。同一句“我不知道”可能有不同作用。机制文件、格式和测试通过均不证明文学效果，效果要看真实完整场景与作者反馈。


## 系统重构如何验证与推广

按作者当前指定的范围与顺序推进，已明确的全量授权不退回试验审批。比较完整交流怎样发生、回应和结束，不能靠动作数、冲突强度或词频证明改进。已有作者认可样本优先参考，合成例子只作说明。详细方法见[系统重构](details/dialogue.md#系统重构如何验证与推广)，实际批次边界以[批次执行](revision-batches.md)和作品当前记录为准。
