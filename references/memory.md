# 有界上下文与连续性

## 数据职责

原始文本和已接受正文保留在本地。资料按主题聚类并富集：同一人物的动机、关系、时点状态和关键证据应相邻，同一事件保留完整因果链，不以每文件短小为目标。二级标题是可检索的主题簇，三级标题保留在所属簇内；索引含主题、实体、时点和来源，允许一个文件很丰富但每次只取有关主题簇。

短接续卡只含当前工作面，建议 1000 汉字以内；它是工作指针，不是整书摘要。活动人物状态与伏笔标明适用章节、状态和来源，可以作为富集档案内的独立主题小节，不必每条一句话拆成文件。较早事件靠索引定位，必要时回读原文。

每个阶段结束可产生一份带原文来源的摘要，保留尚有后果的选择、损失、承诺和未解线索；不层层只压缩上一次摘要。摘要可重建，原文不删。已解决线索保留回收位置，在常规任务包中不加载，回收复核时仍能查到。

## 检索助手

Python 3.10 或更新版本的标准库即可，不联网、不调用模型、不读工作区以外的路径。下列目录名与实体名仅作示例；实际扫描路径由 `novel-workspace.json` 指定，通用配置示例见 `examples/minimal/`。采用其他目录名时显式标注记录元数据，不依赖目录推断类别。

```text
python <skill>/scripts/context.py index --root <工作区>
python <skill>/scripts/context.py build --root <工作区> --mode discuss --query "妹妹 好友 死亡 调查" --ids P001 P002 E002 --budget 9000
python <skill>/scripts/context.py build --root <工作区> --mode clues --ids F002 --budget 7000
python <skill>/scripts/context.py build --root <工作区> --mode character --select "02_人物/P002_妹妹.md#知情边界" --budget 7000
python <skill>/scripts/context.py build --root <工作区> --mode draft --at-chapter 8 --brief 08_写作/任务/第008章.md --ids P001 --budget 12000
```

`index` 写入可重建的 `.novel-cache/index.json`，终端只报告数量。`build` 每次从配置指定目录重新扫描，不依赖可能过时的缓存；按稳定 ID、元数据别名和关键词排序。每次按文件当前内容计算 hash，输出路径、行号、状态和相关原文。默认不检索 00_来源、正文全文、工具研究和所有风格样本。需要时用 `--include <相对文件路径>` 明确加入。

`--budget` 是整个输出包的字符上限，不是精确 token 上限，更不是本次会话总费用。索引读取与本地扫描不会把全部文件放入对话，但此前聊天和额外回查仍占上下文。助手必须控制后续读入，不能生成小资料包后又读全库。

接续卡、用户指定的文档/主题簇和匹配 `--ids` 的主档必须完整纳入；超过预算则报错，不把关键规则截成半句。档案富集后可用 `--select "相对路径#二级标题"` 选取完整主题簇，不要求缩写或拆散原档。其余资料按小节检索，列出遗漏数量和少量回查位置。遇到待决条件或证据不足，缩小任务、增加针对性回查；不能把“未检索到”说成“不存在”。

只查 P001 不代表一定覆盖所有约束，引用规则 ID 或证据文件可补取；同义改写可能漏检，必要时用 `rg` 搜索。脚本负责选材料，人物推演和逻辑判断由助手完成。

## 记录元数据

需要机器选择的 Markdown 首行使用单行 JSON 注释。文件内二级标题之后也可加一条同格式注释，覆盖该主题簇的状态、章节和 ID，保留其他文件级字段；同一个主题簇只放一条。例如：

```markdown
<!-- novel-meta: {"id":"P001-S008","kind":"state","status":"accepted","chapter":8,"entities":["P001"],"aliases":["哥哥"],"sources":["10_正文/第008章.md"]} -->
```

- `id`：稳定标识；`kind`：character/event/clue/rules/state/brief/delta/style 等。
- `status`：plan、candidate、approved、accepted、canonical、resolved、superseded；三者须区分：approved 计划、accepted 正文事实、canonical 已确定规则。
- `chapter`：该记录首次可用的叙述章节，整数；不是故事的物理日期。
- `entities`：实际涉及的实体 ID；`aliases`：明确别名；`sources`：证据来源，不会自动全文加载。
- 同章多场景、倒叙和多视角，须在正文中继续记录事件时间、场景、知情人和信息获得途径。脚本的章节过滤不能代替这些判断。

脚本在有 `--at-chapter` 时排除后续章节记录。在 draft/review 模式下，默认不纳入 plan/candidate/resolved/superseded，也不把未标时点的角色、事件、状态或伏笔当作有效当前状态。世界规则、风格和本次已批准任务可加载。通过 `--include` 也不能绕过时点过滤。前期混合多个未来阶段的旧人物文件仅用于讨论；正式写作前从已授权内容形成对应时点卡。

脚本不替作者批准任务；draft 要求传入 `kind=brief, status=approved` 且章节一致的任务卡。若用户已经授权，由助手根据会话记录补卡即可，不重复问。

## 变更与失效

新章或修订被接受后，按下节完成资料同步与正文归档。保持同一条变更 ID 只应用一次，避免重复增加物品或重复结算死亡。脚本不自动更改正史。

修改早期事实时，沿人物/事件/伏笔引用检查下游，而非重写全书。失效摘要标为待核对，并记录原因；没查原文前不把它当事实。不同人物、地点和叙事线的信息不天然互通，须有获知途径；作者资料中已知的未来事件不等于角色已知。

## 章节审核完成后的归档

作者明确“本章修改完毕”“审核完成”或同等定稿意思时，按工作区约定执行，无须重复索取接受确认。仅说改了几处、要求再审或讨论方案，不触发归档。

先读取实际最终稿，不沿用助手上一版摘要；保留作者修改来源和已授权的小修依据。更新受影响的情节资料、人物个人档案及性格卡、阶段知情与关系、物品/伤病/地点、章末状态和伏笔，并附章节出处。人物的新增侧面、成长或策略变化需有文本依据；单次情绪不直接升格为终身性格，未出现的设计仍为候选。旧候选摘要标为被最终稿替代，未来事件不写成已发生。

资料更新完成后，将最后修改稿复制一份进入配置或工作区约定的正文目录；沿用章节命名，不搬走草稿，不另写正文措辞。已有同章正文时先保留旧版和依据，再应用明确获准的新版，不能覆盖另一候选文件。核对源稿与正文副本的内容或字节一致，记录版本位置和必要的计数/hash；重建索引并让接续卡指向新正文。复制或校验未成功时，不报告已经归档。

归档只处理已完成章节；没有续写授权，不因更新了章末状态自行开始下一章。

## 预演顺序与动态编号

活动大纲、场景清单及对外展示的序号按实际情节预演顺序维护，不按讨论日期或建档先后。分别记录故事发生时点、叙述/揭示时点和讨论来源；倒叙、隐藏前史不因时间早就自动排在开篇。

每次新增、插入、拆分、合并或移位，先判断前置条件与后果，再重排受影响序号，同步任务卡和上下游引用。已进入正文的内容标明承接位置，旧候选不能使其再发生一次。比较变更前后项目集合：每项须仍存在、注明合并去向、列为待排或保留否决原因；伏笔分别检查埋设、推进、回收，跨阶段事件不能只挂在最后。

稳定ID用于追溯，可变序号用于展示；不要用ID数字推断发生顺序。需要更改既有ID或文件名时，留下旧新映射并更新相关引用、链接、元数据与索引，历史来源仍可追溯。未定的先后、并行线和待出场角色单列并写明已有约束，不能按讨论顺序强排。章节合并拆分后更新未来候选章号；已定稿章节不因新讨论擅自改号或改写。

## 衣着抽样的执行记录

作品有每事件衣着概率约定时，记录键为稳定人物ID+稳定事件/子事件ID，另存概率、随机值、触发与否、待写/已使用状态及落笔位置。检查既有记录后才抽，未触发也保存，跨章、返回、修稿与下一轮接续不重抽。首次直接介绍或已有衣着描述可记录为已使用，不能因没有随机数再补一段。

该表是写作调度记录，不是人物心理、世界机制或已发生穿着事实；不要把未来触发项写入角色当前状态。服装事实从实际正文中另取，审核状态沿用该稿。事件拆分合并检查对应与是否已经使用，避免变更编号后重复抽样。
