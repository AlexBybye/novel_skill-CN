# 全书对白专项：批次执行、记录与验收

## 一、受理与基线

- 作者本次已明确授权**全书全量对白精修**。收到小说文件后应直接执行，不必逐章请示；未收到正文，不能假称已通读或精修。
- 取得最新现行稿后固定输入路径、版本/提交号或 SHA-256，并记录章节目录。若有 0 章、插章、小数章节、番外或尾声，按作者当次指定的范围逐项纳入；**不按记忆默认章数、人物、死亡或结局**。
- 同章多版本先根据作者当前指定及现行目录确认正式输入，不能靠括号数字猜新旧。不得把并行分支、备份或旧稿混入同一基线。
- 正文是细节事实依据。档案是辅助。旧诊断的章节定位必须用现稿重新核查，核查不符不做相应修订。
- 目标目录与源目录分开；作品已有 Git、备份和覆盖约定时遵守其要求。绝不误把未审完的副本覆盖唯一原件。

## 二、正式全量前：作者标准校准

在 [作者样本校准协议](editorial-calibration.md) 下使用现行稿里作者明确认可的对白及可获得的人工修改前后对照。先小样本试运行，比较原稿与修改稿；把作者批准的保留、修改、拒绝理由纳入校准札记。没有作者给出的额外样本不应阻止已授权任务，但必须诚实说明尚无人工对照验证，采取更保守的改法。样本一经作者反对，不得继续当正例。不能把某模型提供的“黑名单”当作金标准。

## 三、逐章、逐场的工作流

**阶段 A：完整读**

1. 读完本章所有内容，建立场景边界；对白包括叙述直接引语、接话、场内信件/电话/消息等有交流作用的段落，但文中关键证词与证据原话默认锁定。
2. 同一场跨章时连读。需要人物习惯依据时，检索其**现行、当时点**的先前交流，必要时看后续直接承接；只读后文作编辑参考，不让角色提前知晓后文。
3. 在编辑的内部笔记写一句话指出场景原有目的与现实活动，以及交流是否真的存在问题。**可以判定“保留，不修改”。**

**阶段 B：修实际问题**

4. 先改人物为何说、如何听、如何接；其次考虑称呼、搭配、语气、整轮话的完整性；最后才处理必要的紧邻动作/心理与台词位置。
5. 保留每个问题场景的信息清晰度与事实。删掉只为逐格核验服务的问答时，确认没有失去后续必须知道的内容及证据原话；修改谨慎表达时，不把可能变成确定。
6. 尽量不改整段叙述；如为修对话不得不改旁白，只限于紧邻对白的重复说明、已有动作与话语的接口，并记录为什么必要。

**阶段 C：独立回读**

7. 暂时忘记“原来修改了哪里”，连续读新场景与整章，检查对话是否依旧像任务管理/问答清单，或被改成同一套短句、抬杠、解释、突然沉默。
8. 回看原稿差异，确认新台词没有补造原稿不存在的誓言、威胁、身份认知、私密信息、称谓关系、亲疏变化。凡是越界，撤回。
9. 复查章头接续、章末承接和相邻章里的关系与知情。早期改了“承诺怎么说”，需要核对后文是否将其当作原话引用；若后文有精确引用，则恢复原话或在现有授权允许范围内同步纯措辞引用，不能改变事实。

**阶段 D：交付**

10. 原稿路径和文件名**逐字保持**，包括正文现有的编号、小数编号、括号和特殊字符；不能私自执行旧版的去 `(1)` 命名要求，除非作者此轮明确重新要求。
11. 图片引用的字符内容、语法、路径、文本、相对顺序一概不变。不要根据是否拿到图片实体决定删掉引用；标题、元数据与代码块不作为对白去改。
12. 保存与原结构一致的完整章节，而非只给被改对白或摘要。未修改的章也应保留或在现有原稿目录中明确标记原样通过。

## 四、严格区分三种完成状态

- `FULL_REVIEWED_EDITED`：读完整章、修改过至少一处对白、二次回读及边界复核已完成。
- `FULL_REVIEWED_UNCHANGED`：读完整章、逐场判断，没找到值得改的对白，正文原样保留。
- `PARTIAL_OR_PENDING`：只扫台词、只看 diff、缺少关键相邻文本、尚未完成回读或仍有未解决越界。**不得计入全书完成数。**

对跨章情境，可增记 `ADJACENT_CHECKED`，但这只是承接核对，不等于已完成该章的全章读审。留记录可采用以下**轻量 TSV**，不要向小说中插入审校卡：

```tsv
chapter_path	input_sha256	status	issue_locations	changes	boundary_check	pending
第xxx章_示例.md	<原稿实际哈希>	FULL_REVIEWED_EDITED	段落开头短引	合并无意义反问，保留关键答复	通过	
第yyy章_示例.md	<原稿实际哈希>	FULL_REVIEWED_UNCHANGED		整场自然，原样保留	通过	
```

不要写伪造的 SHA 或编造完成记录。对长篇，允许每批只写一行章节摘要；修改清单与真实差异由 Git/diff 留存。

## 五、批次划分与多代理协作

- 以实际场景的连贯性划批，**不限固定章数**。情绪冲突延续到下一章时，先连读再分别编辑；前文一处改动会影响后文引用时纳入核对。
- 代理上下文不能容纳全书时，先给本批**完整正文**以及必要的邻章、当前人物档案；不要只给片段摘要便要求完成“全章”。
- 未经用户授权，不擅自并行多个代理直接改同一目录。用户若已授权多代理：为每个代理分配唯一写入区间和同一输入基线，跨边界场景由主编辑统一审稿，禁止两个代理覆盖彼此改动。
- 各代理都只能在**对白权限**内更改，不因为负责某个副本就重新考虑事件、配角整合或设定修补；主编辑负责统一确认声口与边界。拆分后的原稿必须重新合并成完整可读章节，不能只拼贴台词片段。

## 六、交付核查

自动检查只承担低级保护：相对路径/文件名一致、章标题一致、图片引用一致、metadata/frontmatter 不变、是否明显截断。可执行：

```bash
python <本技能目录>/scripts/verify_manuscript.py --source <原始章节目录> --revised <精修输出章节目录>
```

然后人工回读两件不能自动化的事情：

1. **文学性**：对话不再被系统核对逻辑牵着走，人物的反应、说话习惯、亲疏距离、生活连续性确有改善；不是新模板替旧模板。
2. **忠实性**：所有非对白内容的修改确有对话接口必要，未越权改变事实、情感进度、动机或信息揭露。程序不能判断这些。

最终报告只需：覆盖章节数量和范围（可核）、改动章节数、原样保留章节数、未完成章节及原因、少量最有代表性的对白问题及修法、结构检查结果。**不得因为模型宣称“已精修”就标记已验证。**

## 七、抽查不能只展示被改得好看的句子

分批后对样本复核：从本批**随机**选场景，也挑情绪高压、修改多、修改少及完全原样保留的场景。采用上下文的 A/B 盲比，问“哪段更像这个人自然在说话、事实是否无损”；不能只计算改动行数，也不能让同一模型自评并宣布达到人工水平。用户无需人工逐章确认，但任何声称“已像作者手修”的结论需要实际的人类偏好或其他可信证据。
