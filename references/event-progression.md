# 事件推进与章节自审

人物档案已有内容而正文仍显工具化，或工作对白、体感与支线牵连失效时，按需查[让人物活在场景里](lived-scenes.md)，从私人诉求进入选择与后果定位问题，不统一补怪癖。

用于整章、连续章节创作或重写，以及推进乏力的诊断。结合当前作品的风格与作者目标选用；不是“每章必有灾难、反转、信物”的公式，也不以字数、短句密度或钩子数量证明质量。平静、舒缓、余波和留白可以成立，需辨认其具体作用。

## 写前：让设定变成人物必须处理的事

- **事件有可追溯的因果。** 梳理触发条件、人物依据、所做选择、直接结果与后续负担。规模来自影响和选择代价，不能只把普通任务换成更大的事故名称。隐藏原因可以暂不揭示，但可见后果应有因果支撑；区分作者知道、读者可推断与角色已有证据，不让角色提前说出谜底。
- **能力改变局面，也留下问题。** 按已确认的条件、对象、范围和代价安排使用；检查它解决了什么、还剩什么、谁须接着行动。多人协作应有各自不可替代的贡献，也保留普通人的判断和专业方法。不能临时削弱、失灵或新增副作用来强造危险，不能为“有代价”擅自增加未批准规则。能力不适用的作品跳过此项。
- **私人牵挂影响公共选择。** 有身份、资源和职责的人会怎样调配资源、判断线索、交接任务、承担风险？把私事放进这些选择及其后果，避免只在工作场景插入几句走神。外部压力可打断计划，但主动调查同样可以有张力；不要把“被动卷入”规定为唯一驱动力。
- **预先辨认本章变化。** 人物或读者在章前、章后，对事实、关系、处境、选择或代价有什么不同？连续几章若只是重复读者已知的失联、担忧和等待，应合并重复、补足获授权的行动后果或重排揭示；不要靠藏住本来会问的问题拖延。

## 成文：让变化有可感知的落点

**情绪与物件。** 优先从既有物件、身体经验、空间和动作中找承载。检查具体对象为何进入视角、人物怎样对待它、它随事件发生了什么意义变化；已有的一双筷子从准备吃饭变成无人使用，比连续添新信物更有力。不强迫所有情绪经过物件，直接心理与对白也可以充分成立；避免把象征意义再逐句解释给读者。

**日常与支线。** 看它是否呈现人物自己的生活、改变关系或选择、形成有效的气氛与节奏。若段落可以在任何位置插入且不影响阅读，应检查是否仅在填篇幅。支线与主线的关联可以通过相似困境下不同的选择体现，不必由旁白点题；不规定每一句都推进主线或兼任伏笔。

**双线与镜像。** 世界线切换默认以上一段落结尾和下一段落开头的相同或相近物象串联，承接画面与情绪，减少读者重新定位的负担；开头仍明确必要的视角、世界和时间落点。按[物象切线](lived-scenes.md#意象切线也要核对时间与物品)检查切换两侧，不仅在章中散放呼应。物品归属、时序及信息通路须成立，不强造同时性，不赋予物象额外异能；作者明确指定的硬切另按其意图执行。

**对白承接。** 逐轮核对对方实际说了什么、本人此刻想获得或避开什么、关系和压力为何支持这句回应。玩笑、追问、坦承未知、拒绝与沉默按场景变化；人物特色不能靠统一斗嘴或审问。沿用[对白承接与场景语气](style.md#对白承接与场景语气)，不虚设误会来凑对话。

## 交付前：用实际文本核对，不凭“已自审”放行

在已有任务卡或自审记录中简短留下必要依据，不另造冗长评分表，不把检查表写进小说：

1. 指出本章实际发生的变化，以及推动它的行动或证据。若只有作者知道的新信息，不能冒充读者已获得的推进。
2. 对关键转折追问“为什么现在发生、为什么此人这样做、结果怎样迫使下一步”。缺少动机、条件或后果，先在已授权范围内修复，再润色句子；不能靠添加形容词和反应动作遮住结构缺口。必须改变重大情节才能成立时，提出具体分歧。
3. 核对关键情绪是否有充分呈现，日常是否在场景里自然发生，能力与专业行动是否守住边界。普通生活可以只供人物相处，不为每句补情节用途；也不以重复摸物件代替情绪发展。
4. 检查章尾留下的是新问题、决定、代价、关系变化还是有分量的情绪余波。仅复述已知担忧通常不能承担悬念；但情绪收束可以是有意落点，不强制砸反转。
5. 连续章节比较各章承担的推进。多拆一章应增加独立而必要的变化或情感展开；只把同一轮等待、核验切碎，应合并或重组。达到字数下限不等于完成了章的任务。

连续性核对和表达审阅分别记录结论。时间、能力、知情和物品无误，只说明这些边界守住了；不能用它们证明对白或情绪已经自然。作者指出声音趋同、交流僵硬或节奏整齐时，读完整关键场景，与少量实际作者样本对照，检查句法、接话、旁白和未被处理完的情绪。标出具体差异及残留，不把某句闲话、一次失言或某个身体细节的存在当作通过凭据。格式、字数和关键词检查只能辅助定位。

记录区分“已检查并修复”“仍有问题”“不适用”，不宣称检查能保证文学质量。保持[草稿与已接受正文的状态边界](memory.md#章节审核完成后的归档)，交付时遇到并行修改按当前文件复核，不能用旧缓存覆盖。
